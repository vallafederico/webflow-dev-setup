# Loader Script

The loader is the single `<script>` you paste into the Webflow site's **head custom code**. It decides where JS and CSS come from on each page load.

Get it from the dev server: run `bun dev`, open `http://localhost:6545`, and click the **Loader Script** box to copy it. It's generated by `generateLoaderScript` in `bin/generateResponse.ts`, with your URLs and file names filled in.

Re-paste and publish whenever you change `VERCEL_URL`, `USE_SSL` or `PREVIEW_HOST_SUFFIX`, or add, rename or remove an entry file. Those values are baked in when it's generated.

## Where files load from

| Situation | JS / CSS loaded from |
|---|---|
| Production domain (anything not `*.webflow.io`) | Vercel deployment (`VERCEL_URL`) |
| `.webflow.io`, desktop | Local dev server first, falls back to Vercel if it fails |
| `.webflow.io`, phone / tablet | Vercel. Localhost on a phone is the phone itself, so the request could never succeed |
| `.webflow.io` with a branch preview | The preview deployment |

Page routing applies everywhere: if `src/pages/<slug>.js` exists, `/<slug>` loads it instead of `app.js`. See [Multiple Entry Points](./multiple-entry-points.md).

## URL parameters

All of these only work on `*.webflow.io`. Production domains ignore them, so a link can never change what live visitors get.

| Parameter | Effect | Remembered for the tab |
|---|---|---|
| `?local=0` | Skip the local dev server, load from Vercel. Also clears `?local=1` | Clears |
| `?local=1` | Try the local dev server even on touch devices, e.g. the iOS Simulator | Yes |
| `?js=<preview url>` | Load JS from a Vercel branch deployment | Yes |
| `?css=<preview url>` | Load CSS from a Vercel branch deployment | Yes |
| `?js=none` / `?css=none` | Don't load our JS / CSS at all, for debugging | Yes |
| `?js=off` / `?css=off` | Clear the preview or `none` setting | Clears |

"Remembered for the tab" uses `sessionStorage`: reloads and navigation in that tab keep the setting, and a new tab starts clean.

A branch preview or `none` turns off the localhost attempt. Branch previews only accept `https` URLs whose host ends in `PREVIEW_HOST_SUFFIX`. Details in [Branch Previews](./branch-previews.md).

## Debugging with `?js=none`

To find out whether a problem comes from our bundle or from Webflow and third-party scripts, open the staging URL with `?js=none` and reproduce. If the problem persists without our JS, it isn't in the bundle. `?js=off` turns it back on.

## Local code in the iOS Simulator

The Simulator shares the Mac's network, so `localhost` inside it reaches `bun dev`. It reports itself as a touch device, though, so the loader treats it like a phone unless you add `?local=1`.

The staging site is HTTPS, so the dev server must be too, and the Simulator must trust its certificate:

1. Create certificates once: `bun run setup-ssl`. See [SSL Setup](./ssl.md).
2. Run the dev server over HTTPS: `USE_SSL=true bun dev`, or set `USE_SSL=true` in `.env`.
3. With the Simulator booted, trust the repo's certificate authority:

   ```bash
   xcrun simctl keychain booted add-root-cert certs/ca.crt
   ```

4. Open `https://your-site.webflow.io/?local=1` in the Simulator's Safari.

If the dev server isn't reachable, the loader falls back to Vercel, as on desktop.

## Why the loader looks the way it does

- **No `crossOrigin`.** Classic (non-module) scripts don't need it. `vercel.json` sends `Access-Control-Allow-Origin: *` anyway.
- **Scripts injected from JS run as soon as they download.** `defer` only applies to `<script>` tags in the HTML, so it has no effect here. Code that needs the whole DOM shouldn't assume the page has finished parsing.
- **Touch detection uses `(pointer: coarse)`,** which matches devices whose primary input is touch, like phones and tablets. Use `?local=1` / `?local=0` to override it either way.
