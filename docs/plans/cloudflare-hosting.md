# Part 1: Cloudflare hosting alongside Vercel

## Goal

A new project picks its host with one command. Pushing then builds and updates the same CDN link, as Vercel does today.

```bash
pnpm connect cloudflare
pnpm connect vercel
```

Existing client sites keep working on Vercel. Nothing here forces a loader re-paste or a Vercel shutdown.

## What is served

Static files from `dist/`, built on push: JS, CSS, `public/` files and build extras. Webflow still serves the pages. API routes are the only code that runs per request. Heavy media is static too, but lives in R2 and is uploaded separately.

## Decisions

| Topic | Decision |
|---|---|
| Cloudflare product | Workers Builds with Static Assets, not Pages |
| Host choice | `pnpm connect <host>`. Not `pnpm setup`, which is a pnpm built-in |
| Settings | Committed `project.config.json`. No `DEPLOY_URL` or `PREVIEW_HOST_SUFFIX` env vars, and no manually set `VERCEL_URL` |
| Cloudflare production URL | `<project>.itsoffbrand.dev`, one Worker per project, DNS and certificate created on deploy |
| Vercel production URL | `<project>.vercel.app` |
| Previews | On each host's default domain. Allowlist limited to this project on Cloudflare, and to the team suffix on Vercel |
| `public/` | Deploys with the code, so previews get their own copies |
| Heavy media | R2 at `<project>-media.itsoffbrand.dev`, reached through `mediaUrl()`, only when a project needs it. Built last, and can ship separately |
| Asset origin | Read in the browser from `document.currentScript.src`, with a build-time fallback |
| API | Cloudflare gets a router generated from `api/*.ts`. Vercel keeps its functions. Handlers don't change, and keep setting their own CORS headers |
| Package manager | pnpm. Bun stays the bundler and dev runtime. Keep `bun` in `devDependencies`: `pnpm build` uses the version pinned in the lockfile (1.3.14), which needs `allowBuilds: bun: true` |
| Deploys on Cloudflare | Git only. `bun dep` prints "push to main" instead of deploying a laptop build |

## Config

`project.config.json`, committed and written by `pnpm connect`:

```json
{
  "host": "cloudflare",
  "name": "acme",
  "deployUrl": "https://acme.itsoffbrand.dev",
  "mediaUrl": null,
  "previewHostSuffix": "-acme.yourteam.workers.dev"
}
```

An unconnected template has no file. Dev still works, and the dev index shows a "run `pnpm connect`" notice where it now asks for `VERCEL_URL`.

## Prove first

Test these on one throwaway project before writing `pnpm connect`, because they can change the design. Deploy through a real Workers Builds push, using this hand-written `wrangler.jsonc`:

```jsonc
{
  "name": "acme",
  "compatibility_date": "<date of connect>",
  "compatibility_flags": ["nodejs_compat"],
  "main": ".generated/worker.ts",
  "assets": { "directory": "./dist", "run_worker_first": ["/api/*"] },
  "routes": [{ "pattern": "acme.itsoffbrand.dev", "custom_domain": true }],
  "preview_urls": true,
  "previews": {}
}
```

Tested on 2026-11-02 with a throwaway Worker, since deleted, deployed from Wrangler 4.156.2 under the logged-in account:

- **Confirmed:** `wrangler preview` serves assets, `_headers` and `run_worker_first` routes. `/_headers` and missing files return 404. Preview URLs are `<branch>-<worker>.<subdomain>.workers.dev`, and a long branch name is shortened with the `-<worker>.<subdomain>.workers.dev` suffix intact. Slashes become dashes. The subdomain can be read from the deploy or preview output.
- **Open:** `itsoffbrand.dev` isn't on that account (`The zone "itsoffbrand.dev" does not exist on your account`), so custom domain creation is untested. `connect` must therefore let the user choose the account and write `account_id` into `wrangler.jsonc`.

Still to test on a real Workers Builds push:

- The Workers Builds token alone can create the custom domain during deploy. Cloudflare documents it as having `Workers Routes (edit)`. The build log must show the domain being created, with no local `wrangler deploy` run against the project.
- The CLI labels `wrangler preview` open beta. Fallback if it regresses: `wrangler versions upload --preview-alias`.
- Workers Builds accepts `main` pointing at a file generated by the build command.
- Workers Builds honours `packageManager: pnpm@11.22.0`, and `pnpm build` runs the pinned Bun.
- Vercel still builds after `bun.lockb` is removed.

### 2. `pnpm connect`

- `bin/connect.ts` (new), with a `"connect": "bun run bin/connect.ts"` script. Accepts flags for every prompt so it can run unattended.
- Validates the name as a DNS label and rejects reserved names such as `www`.
- Validates the suffix against `/^[-.][a-z0-9.-]+$/` and lowercases it, so `yourteam.vercel.app` can't also match `evil-notyourteam.vercel.app`.
- Safe to re-run: shows existing values as defaults, asks before changing the host, and keeps an existing `compatibility_date`.
- **`cloudflare`:**
  - Runs `wrangler whoami` and stops with instructions if not logged in.
  - Looks up the `workers.dev` subdomain, or asks once.
  - Asks for the base domain, defaulting to the `WF_BASE_DOMAIN` env var. The template is public, so `itsoffbrand.dev` is not hard-coded.
  - Writes `project.config.json` and `wrangler.jsonc`, then prints the dashboard steps: connect the repo, set the build command to `pnpm build`, enable non-production builds.
- **`vercel`:** asks for the team suffix, writes `project.config.json`, prints the dashboard steps. `vercel.json` already exists.
- Neither path deletes the other host's config, so a project can run on both during a move.

The Cloudflare suffix also matches any Worker in the same account whose name ends in `-acme`. That's accepted, since those Workers are all yours.

### 3. Cloudflare pieces

- `bin/build.ts`, when `host` is `cloudflare`:
  - Write `dist/_headers` with the same CORS and `.glb`/`.gltf` rules as `vercel.json`. It isn't committed to `public/`, because Vercel would serve it publicly.
  - Run the worker generator.
- `bin/generate-worker.ts` (new): writes `.generated/worker.ts`, importing top-level `api/*.ts` like `bin/api.ts` does.
  - Requests for missing assets also reach the Worker, so return 404 for anything outside `/api/`.
  - Dispatch through an explicit method allowlist (`GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`). Return 405 for a method the route doesn't export and 404 for an unknown route.
  - An empty `api/` folder gives a router that always returns 404.
- `bin/deploy.ts`: on `cloudflare`, print that pushing to `main` deploys, then exit. On `vercel`, call the existing hook.
- `package.json`: add `wrangler` (4.135 or newer) to `devDependencies`, and update `pnpm-lock.yaml`.
- `.gitignore`: add `.generated` and `.wrangler`.

Update `README.md`, `CLAUDE.md`, `docs/setup.md`, `docs/config.md`, `docs/loader.md`, `docs/branch-previews.md`, `docs/css-issues.md` and `docs/env-configuration.md`. ### 5. R2 media

Last, so it can't hold up the rest.

- `pnpm connect cloudflare --media`:

  - Attaches the domain with `wrangler r2 bucket domain add`, which needs a zone ID, so it asks or reads `WF_ZONE_ID`.
  - Sets CORS with `wrangler r2 bucket cors set`, so WebGL and `fetch` can read the files.
  - Writes `mediaUrl`.

# Part 2: Checks agents can run on their own work

## Goal

An agent can tell whether its work is correct without asking anyone or judging by eye. Every check is a command with a fixed result for the same code: no AI, no network in the fast tier, tools pinned by the lockfile. Anything a machine can't decide, such as whether an animation feels right, stays in the skills.

## Commands

| Command | What it runs | When |
|---|---|---|
| `pnpm check` | Format, Biome lint, `tsc`, house rules, unit tests | After every change. Target under 15 seconds, no network |
| `pnpm check:all` | The above, plus production build, bundle checks, host checks, browser run | Before saying work is done, and in CI |
| `pnpm check:live` | Compares the deployed files with the current commit, on either host | After a push |
| `pnpm fix` | Applies safe autofixes: formatting, import paths | Whenever |
| `pnpm new:module <name>` | Writes a module that already passes every rule | Starting a module |

Every check command accepts `--json` and returns the same shape, sorted so the output is stable:

```json
{
  "ok": false,
  "checks": [
    {
      "name": "house-rules",
      "ok": false,
      "findings": [
        {
          "rule": "cleanup/state-listener",
          "severity": "error",
          "file": "src/modules/nav.ts",
          "line": 11,
          "message": "State.on has no matching State.off, so the listener outlives the page",
          "fix": "Call State.off with the same handler inside onDestroy"
        }
      ]
    }
  ]
}
```

Exit codes: `0` passed, `1` findings, `2` the tool itself failed. Agents must not read a tool failure as a pass.

## Tools

- **Biome** for formatting and general lint. Its JSON output works in 2.6.4.
- **`tsc --noEmit`** for types, about a second today. Add `"include": ["src", "bin", "api"]` to `tsconfig.json`, because it currently also checks `dist/`. Biome ignores `dist` and `.generated` too.
- **House rules** in `bin/check/house-rules.ts`, using the TypeScript compiler API. It can follow patterns across a file, and we control the output. Biome's GritQL plugins and Oxlint's JS plugins were the alternatives, but Oxlint's plugin API was still alpha in the latest release notes found, and neither gives us this `fix` output. Move `typescript` from `peerDependencies` to `devDependencies`, pinned to `5.9.x`, because newer major versions have a different API.
- **Playwright** for the browser run, against the local build.

## House rules

Each rule comes from the existing skills and Cursor rules, and was checked against `src/`. `Today` is what it flags in the current code. `imports/*` and `browser/no-process-env` cover all of `src/`. The others cover `src/modules/*.ts`, and `src/pages` where noted.

| Rule | Enforces | Today |
|---|---|---|
| `module/default-export` | `src/modules/*.ts` has a default-exported function | 0 |
| `module/signature` | `(element: HTMLElement, dataset: DOMStringMap)`, or fewer parameters | `nav.ts`, `split.ts` |
| `module/filename` | Kebab-case, not generic names like `module.ts` | 0 |
| `imports/lifecycle` | Hooks come from `@/modules/_`. Autofixable | `split.ts` |
| `imports/subs` | Subscriptions come from `@lib/subs`. Autofixable | `cycle.ts`, `nav.ts`, `_/runner.ts`, `utils/tick.ts` |
| `imports/gsap` | GSAP comes through `@lib/gsap`, except in `src/lib/gsap.ts` | 0 |
| `subs/no-raw` | No `requestAnimationFrame` or resize listener in modules and pages | 0 |
| `cleanup/subscription` | The result of `Raf.add`, `Resize.add` or `Scroll.add` is kept and called in `onDestroy` | Measured when built |
| `cleanup/state-listener` | Each `State.on` has a matching `State.off` with the same function, so an inline arrow always fails. `State.once` is exempt, and `State` is resolved through its import, not its name | `cycle.ts`, `nav.ts` |
| `cleanup/listener` | `addEventListener`, `setInterval` and observers are undone in `onDestroy` | Measured when built |
| `boot/no-body-at-load` | Warning only: `document.body` at the top level of a file. The real incident went through a function call, which only the browser run can catch | Measured when built |
| `browser/no-process-env` | No `process.env` in `src/`, except `NODE_ENV`. Would have caught the `apiPath` bug | `api-path.ts`, `url-validator.ts` |
| `editor/handled` | A module that calls `Raf.add`, `onView` or GSAP must use a new `onEditor()` lifecycle helper, which wraps `handleEditor` and releases the listener in `onDestroy`. Unused imports don't count. `Scroll` and `onTrack` are exempt, because `src/lib/scroll.ts` already destroys Lenis in the editor | `cycle.ts`, `split.ts` |

`console.log` in modules is a warning, not a failure, because the debugging rules encourage it while developing.

An exception needs a stated reason on the line above: `// house-ignore <rule>: <reason>`. A missing reason is itself a finding, so agents can't silence a rule without explanation.

Rules match syntax, so they can miss things. For example, a cleanup function passed through a helper is invisible to them. The browser run catches those by behaviour instead.

## Browser run

Taxi is opt-in. It's commented out in `src/app.ts` and `src/lib/pages.ts`, so links are full page loads and `onDestroy` never runs in the template. A test through real navigation would therefore always pass, so the run drives the lifecycle directly.

`bin/check/runtime.ts` builds two things:

- **The production bundle.** Nothing test-related ships in it.
- **A test bundle** from `bin/check/fixture-entry.ts`, which imports the same modules and lifecycle functions and exposes them on `window`.

It serves them locally with generated fixture pages containing one `data-module` element per module, and a favicon. A module that needs specific markup can add `src/modules/<name>.fixture.html`, which the module glob ignores. It then:

1. **Normal load:** loads the production bundle. Fails on an uncaught error or a `console.error` that isn't a network 404.
2. **Early load:** loads the production bundle from a synchronous `<script>` in `<head>`, so it runs before `<body>` exists. Fails on any error. This is the incident in `docs/loader.md`.
3. **Leak test:** in the test bundle, runs `createCycles`, `runPageIn` and `runMount` and records counts. Then it runs `runPageOut` and `runDestroy`, replaces the fixture DOM, and mounts again. Fails if any count grew. The DOM must be replaced because `createCycles` skips elements it has already initialized.
4. **Editor load:** repeats the load with the Webflow editor marker in the page, and fails on any error.
5. **Taxi navigation:** only when `checks.config.json` has `"taxi": true`, also follows a real link between fixture pages wrapped in `data-taxi` and `data-taxi-view`.

The counts cover `Raf`, `Resize`, `Scroll`, `State` and editor listeners, through a small `count()` method on each. It has to be a method: `src/lib/hey.ts` binds any `State` property it finds, so a `size` getter would throw.

It doesn't cover real Webflow markup, how things look, or real devices.

## Bundle and host checks

Part of `pnpm check:all`:

- **Bundle:** gzip size per entry against budgets in `checks.config.json`, starting 10% above current sizes. `.js`, `.css` and `.txt` files in `dist/`, not source maps, must contain no `localhost` URL or leftover `__PUBLIC_ASSET_ORIGIN__`. All of `dist/`, including source maps, must contain no secret values: only `.env` keys matching `hook`, `token`, `secret` or `key`, with values of 16 characters or more. Scanning every value would fail on `USE_SSL=true`.
- **Host config, both hosts:** `project.config.json` is valid, and each `api/*.ts` exports only HTTP method handlers.
- **Cloudflare:** `wrangler.jsonc` matches the config's name and domain, the generated `_headers` matches the rules in `vercel.json`, and `wrangler deploy --dry-run` passes.
- **Local serving:** the header and route checks from Part 1, done check 4, become a script instead of a manual step.

`pnpm check:live` works the same on both hosts:

- The build writes the commit into `build-manifest.json`, from `WORKERS_CI_COMMIT_SHA` or `VERCEL_GIT_COMMIT_SHA`, and writes relative file paths instead of the current absolute ones.
- It exits 2 straight away if the working tree is dirty or `HEAD` isn't pushed, because no deployment can match.
- On `main` it checks `deployUrl`. On any other branch it requires `--url <preview url>`, because `deployUrl` only follows `main`.
- It fetches the manifest with no cache, retrying for a few minutes until it matches `git rev-parse HEAD`.
- It then checks that each JS and CSS file returns 200 with the right content type and CORS header.

Part 1's done check 8 can then be run by an agent, once the project has been connected.
